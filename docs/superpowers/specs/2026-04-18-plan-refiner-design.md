# Plan Refiner — Design Spec

**Date:** 2026-04-18
**Status:** Approved

---

## Problem

Implementation plans generated by LLMs (like the `docs/superpowers/plans/` files produced by the `writing-plans` skill) are single-pass outputs. No adversarial review catches missing tasks, wrong dependency order, vague steps, insufficient test coverage, security gaps, or architectural inconsistencies before a developer starts executing them.

---

## Goal

A `plan` CLI subcommand that runs a multi-LLM convergence loop on a PLAN.md file until no reviewer can find a new valid issue with it. Seven configurable personas review from distinct angles. Output is a revised, converged plan plus optional companion artifacts.

---

## Approach

Full mirror of document mode (Approach A). `PlanConfig`, `PlanRefiner`, `plan_strategy.py`, `plan_loop.py` are parallel to their document-mode counterparts. Zero changes to existing document mode code. `hitl.py`, `backends/`, `prompts.py` reused as-is.

---

## Design

### 1. Data Model

No new types. Reuses the document mode data chain verbatim:

```python
RawCritique      # from Challenger or any persona
VerifiedCritique # from Verifier: status = "valid" | "stale" | "deferred"
Patch            # from Arbitrator: section_ref + proposed_text + rationale
Issue            # registry entry: id + status + defer_reason + verified_cycle
```

**New dataclasses in `src/config.py`:**

```python
@dataclass(frozen=True)
class PlanPersonaConfig:
    name: str
    prompt_file: str = ""   # defaults to f"plan_persona_{name}.md"

@dataclass(frozen=True)
class PlanConfig:
    topic: str
    goal: str
    primary_artifact: str = "PLAN.md"
    source_material: str = ""
    convergence_cycles: int = 2
    max_cycles: int = 10
    persona_mode: str = "parallel"
    personas: tuple[PlanPersonaConfig, ...] = (
        PlanPersonaConfig("architect"),
        PlanPersonaConfig("tech_lead"),
        PlanPersonaConfig("qa_engineer"),
        PlanPersonaConfig("ai_engineer"),
        PlanPersonaConfig("data_engineer"),
        PlanPersonaConfig("security_engineer"),
        PlanPersonaConfig("devils_advocate"),
    )
    artifacts: tuple[ArtifactConfig, ...] = ()
    source_files: tuple[SourceFileConfig, ...] = ()
    backends: BackendsConfig = field(default_factory=BackendsConfig)
    strategy_config: StrategyConfig = field(default_factory=StrategyConfig)
```

`PlanConfig.from_yaml()` loads from a YAML file with a top-level `plan:` key. Path resolution and `source_files` glob expansion follow the same rules as `DocumentConfig.from_yaml()` (delegating to `_parse_source_files()`).

---

### 2. YAML Syntax

```yaml
plan:
  topic: "source_files feature"
  goal: >
    A complete, unambiguous implementation plan that a senior engineer
    can execute task-by-task without clarifying questions.

  primary_artifact: "PLAN.md"
  source_material: ""          # optional path to an existing draft plan

  convergence_cycles: 2
  max_cycles: 10
  persona_mode: parallel       # parallel | serial

  personas:
    - name: architect
    - name: tech_lead
    - name: qa_engineer
    - name: ai_engineer
    - name: data_engineer
    - name: security_engineer
    - name: devils_advocate

  source_files:
    - path: docs/superpowers/specs/**/*.md
      roles: [builder, architect, tech_lead]
    - path: PRD.md
      roles: [all]

  artifacts:
    - name: RISK_REGISTER.md
      layer: companion
      review: false

  backends:
    primary: claude
    research:
      - claude                 # Builder (research[0])
      - gemini                 # Challenger (research[1])
    judge: claude              # Arbitrator
    utility: gemini            # Verifier
```

### 3. PlanStrategy (`src/plan_strategy.py`)

Mirrors `ConvergeStrategy`. Five steps per cycle:

| Step | Agent | Backend role | What it does |
|------|-------|-------------|--------------|
| 1 | **Builder** | `research[0]` | Applies patch list; produces revised PLAN.md (full rewrite) |
| 2 | **Challenger** | `research[1]` | Finds structural gaps: missing tasks, wrong order, vague steps, undefined references |
| 3 | **Personas** | `primary` | Each persona reviews from its domain lens (see below) |
| 4 | **Verifier** | `utility` | Classifies each critique: `valid`, `stale`, or `deferred` |
| 5 | **Arbitrator** | `judge` | Merges valid critiques into concrete patch list |

Personas run concurrently (`persona_mode: parallel`) or sequentially (`serial`).

**`_source_block(role: str) -> str`** — identical to document mode. Lazy file reads per call, heading included only when files are present.

---

### 4. Persona Critique Angles

| Persona | Prompt file | What it looks for |
|---|---|---|
| **Architect** | `plan_persona_architect.md` | File boundaries, responsibility separation, coupling between tasks, consistency with existing codebase patterns |
| **Tech Lead** | `plan_persona_tech_lead.md` | Task sizing (too big → needs splitting), dependency order, commit granularity, naming consistency |
| **QA Engineer** | `plan_persona_qa_engineer.md` | TDD discipline (test before implementation), edge case coverage, missing integration tests, flaky test setups |
| **AI Engineer** | `plan_persona_ai_engineer.md` | Prompt template correctness, model/backend selection rationale, evaluation strategy, non-determinism handling |
| **Data Engineer** | `plan_persona_data_engineer.md` | Data flow correctness, schema migration order, ETL sequencing, missing rollback steps |
| **Security Engineer** | `plan_persona_security_engineer.md` | Input validation gaps, injection surfaces, auth/authz assumptions, secrets handling, unsafe subprocess patterns |
| **Devil's Advocate** | `plan_persona_devils_advocate.md` | Hidden assumptions, skipped "obvious" steps, missing error handling tasks, mid-task failure scenarios |

**Challenger** (distinct from personas): structural plan problems only — missing tasks, tasks in wrong order, steps too vague to execute, steps referencing symbols not yet defined in the plan.

### 5. Prompt Templates

All prompts use `{variable}` injection, JSON I/O (same schemas as document mode).

**`prompts/plan_builder.md`**
- Inputs: `{topic}`, `{goal}`, `{source_material}`, `{source_files}`, `{current_plan}`, `{patches}`, `{human_decisions}`
- Instruction: apply every patch, preserve plan header and all checkbox syntax (`- [ ]`), keep unpatched tasks verbatim, output full revised plan

**`prompts/plan_challenger.md`**
- Inputs: `{topic}`, `{plan}`, `{source_files}`
- Instruction: structural gaps only — missing tasks, wrong order, vague steps, undefined symbol references
- Output: JSON array of `RawCritique`

**`prompts/plan_persona_{name}.md`** (7 files)
- Inputs: `{plan}`, `{topic}`, `{source_files}`
- Output: JSON array of `RawCritique`

**`prompts/plan_verify.md`**
- Inputs: `{plan}`, `{critiques_json}`
- Output: JSON array of `VerifiedCritique` (`valid` | `stale` | `deferred`)

**`prompts/plan_arbitrate.md`**
- Inputs: `{plan}`, `{valid_critiques_json}`
- Output: JSON array of `Patch`

### 6. PlanRefiner (`src/plan_refiner.py`)

Mirrors `DocumentRefiner`. Three phases:

**Phase 1 — Convergence:** Cycle loop until `convergence_cycles` consecutive clean cycles or `max_cycles` reached. Writes `.run/cycles/cycle_NNN.md` and `.run/PLAN_vN.md` snapshots each cycle.

**Phase 2 — Expansion:** Generates configured `artifacts` from the converged plan.

**Phase 3 — Indexing:** Auto-generates `README.md` and `DOCS_INDEX.md` using existing `generate_readme.md` and `generate_docs_index.md` prompts.

Exit codes: `0` (success), `1` (error), `2` (human input required in non-interactive mode).

---

### 7. Plan Loop (`src/plan_loop.py`)

Mirrors `document_loop.py`. Defines `PlanCycleState` and `run_plan_cycle()`.

`PlanCycleState` fields:
- `plan: str` — current plan text
- `cycle: int`
- `consecutive_clean_cycles: int`
- `issue_registry: list[Issue]`
- `pending_human_inputs: list[HumanInputRequest]`
- `human_decisions: list[HumanDecision]`

Convergence condition identical to document mode: clean = no valid critiques + no `human_required` deferrals in a cycle.

---

### 8. CLI (`src/cli.py`)

New `plan` subcommand:

```bash
uv run python -m src.cli plan --config configs/my_plan.yaml
uv run python -m src.cli plan --config configs/my_plan.yaml --no-interactive
uv run python -m src.cli plan --config configs/my_plan.yaml --resume
uv run python -m src.cli plan --config configs/my_plan.yaml --output ./docs/refined
```

Flags: `--config` (required), `--output`, `--resume`, `--no-interactive`. Identical to `refine`.

---

### 9. Output Artifacts

Written to `output/<config-stem>/` (or `--output <dir>`):

| File | Description |
|---|---|
| `PLAN.md` | Converged plan |
| `RISK_REGISTER.md`, … | Phase 2 companions (as configured) |
| `README.md` | Auto-generated orientation guide |
| `DOCS_INDEX.md` | Auto-generated artifact index |
| `.run/run_manifest.json` | Cycles, cost, token counts, finished_at |
| `.run/issue_registry.json` | All critiques with final status |
| `.run/cycles/cycle_NNN.md` | Per-cycle snapshot |
| `.run/PLAN_vN.md` | Full plan snapshot after each cycle |
| `.run/pending_questions.json` | Deferred HITL questions |
| `.run/human_decisions.json` | Audit trail of human answers |

---

### 10. Config Template (`configs/plan_template.yaml`)

Annotated reference covering all fields, role targeting examples, and persona customization.

---

## Error Handling

Identical to document mode:

| Condition | Behavior |
|---|---|
| Literal `source_files` path not found | `ValueError` at `from_yaml` time |
| Glob matches nothing | `log.warning(...)`, skip silently |
| File unreadable at call time | `log.warning(...)`, skip that file |
| Prompt file missing for persona | `log.warning(...)`, skip that persona for the cycle |
| Human input required, non-interactive | Write `.run/pending_questions.json`, exit code 2 |
